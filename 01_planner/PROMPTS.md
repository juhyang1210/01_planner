# Smart Campus Planner 구현 요청 프롬프트 모음 (PROMPTS)

이 문서는 `PRD.md`(무엇을 만들지)와 `TASKS.md`(어떤 순서로 만들지)를 바탕으로,
실제로 AI 코딩 도구(Cline 등)에게 **한 단계씩 구현을 요청할 때 그대로 복사해서 사용할 수 있는 프롬프트**를 정리한 문서입니다.

## 사용 방법
1. 아래 **T1 프롬프트**를 그대로 복사해서 AI에게 전달합니다.
2. 결과물이 나오면 "T1 결과 확인 체크리스트"를 보면서 직접 눌러보고 확인합니다.
3. 문제가 없으면 **T2 프롬프트**로 넘어갑니다. (문제가 있으면 T1 프롬프트 아래에 "이 부분이 이상하다"고 덧붙여 다시 요청하면 됩니다.)
4. T2 확인이 끝나면 같은 방식으로 **T3 프롬프트**를 진행합니다.

> 한 번에 전체를 요청하지 않고, 반드시 T1 → 확인 → T2 → 확인 → T3 → 확인 순서로 진행하는 것을 권장합니다.

---

## T1. 할 일 등록·저장 기본 기능 만들기

### 목표
`TASKS.md`의 "작업 1"에 해당하며, 할 일을 추가/분류/완료/삭제하고 새로고침해도 사라지지 않게 저장하는 가장 기본적인 기능을 만듭니다.

### 그대로 복사해서 사용할 요청 프롬프트

```
Smart Campus Planner라는 대학원생용 할 일 관리 웹앱을 만들고 있어.
지금은 전체 기능 중 첫 번째 단계만 구현해줘. 아직 캘린더나 완료율 기능은 만들지 마.

[만들어야 할 것]
1. HTML, CSS, 자바스크립트만 사용해서 브라우저에서 바로 열어볼 수 있는 웹페이지로 만들어줘.
   (별도 설치나 서버 없이 index.html 파일을 더블클릭해서 열면 바로 실행되게 해줘.)
2. 화면에 할 일을 새로 입력할 수 있는 입력 폼을 만들어줘. 입력 항목은 다음과 같아.
   - 할 일 제목 (텍스트)
   - 카테고리 (BK / 랩실(수업) / 프로젝트 / 스터디 / 개인 중 하나를 선택)
   - 중요도 (상 / 중 / 하 중 하나를 선택)
   - 시작일 (날짜 선택)
   - 마감일 (날짜 선택)
3. "추가" 버튼을 누르면 위에서 입력한 내용이 아래쪽 할 일 목록에 새로운 항목으로 나타나야 해.
4. 목록에 있는 각 할 일에는 다음 기능이 있어야 해.
   - 완료 여부를 체크할 수 있는 체크박스 (체크하면 완료 표시, 다시 누르면 취소)
   - 삭제 버튼 (누르면 그 할 일이 목록에서 사라짐)
5. 브라우저의 로컬 저장소(localStorage)를 사용해서, 할 일을 추가/완료/삭제할 때마다 자동으로 저장하고,
   페이지를 새로고침하거나 다시 열어도 저장된 할 일 목록이 그대로 남아있게 해줘.
6. 디자인은 화려하지 않아도 되지만, 각 항목(제목/카테고리/중요도/기간/완료여부)이 한눈에 구분되게 보여줘.

이번 단계에서는 완료율 표시나 캘린더 화면은 만들지 말고, 위 내용까지만 구현해줘.
```

### T1 결과 확인 체크리스트
- [ ] `index.html` 같은 파일을 더블클릭했을 때 브라우저에서 바로 열린다.
- [ ] 제목, 카테고리, 중요도, 시작일, 마감일을 입력하고 "추가" 버튼을 누르면 목록에 새 항목이 생긴다.
- [ ] 목록에서 체크박스를 누르면 완료 표시로 바뀌고, 다시 누르면 원래대로 돌아온다.
- [ ] 삭제 버튼을 누르면 해당 항목이 목록에서 사라진다.
- [ ] 할 일을 몇 개 등록한 뒤 브라우저를 새로고침(F5)해도 등록한 할 일이 그대로 남아있다.
- [ ] 위 항목이 모두 정상이면 T2로 진행합니다.

---

## T2. 전체 완료율 표시 및 목록 화면 다듬기

### 목표
`TASKS.md`의 "작업 2"에 해당하며, T1에서 만든 할 일 데이터를 활용해 전체 완료율을 보여주고,
카테고리와 중요도를 목록에서 시각적으로 구분되게 다듬습니다.

### 그대로 복사해서 사용할 요청 프롬프트

```
지금까지 만든 Smart Campus Planner의 할 일 등록/저장 기능(T1)에 이어서,
두 번째 단계 기능을 추가로 구현해줘. 기존에 만든 할 일 추가/완료/삭제/저장 기능은 그대로 유지하고,
아래 내용만 추가해줘.

[추가로 만들어야 할 것]
1. 화면 상단(또는 눈에 잘 띄는 위치)에 "전체 완료율"을 보여줘.
   - 계산 방법: (완료된 할 일 개수 ÷ 전체 할 일 개수) x 100, 퍼센트(%)로 표시
   - 전체 할 일이 하나도 없을 때는 0%로 표시해줘.
   - 할 일을 추가하거나, 완료 체크를 하거나, 삭제할 때마다 이 퍼센트가 즉시 다시 계산되어 화면에 반영되어야 해.
2. 할 일 목록에서 카테고리를 색깔로 구분해줘.
   - BK, 랩실(수업), 프로젝트, 스터디, 개인 각각 서로 다른 색을 사용해서
     목록의 각 항목에서 카테고리를 한눈에 알아볼 수 있게 해줘. (예: 항목 왼쪽에 색깔 띠, 또는 카테고리 이름에 배경색 등)
3. 할 일 목록에서 중요도(상/중/하)도 눈에 띄게 구분해줘.
   - 예를 들어 "상"은 눈에 잘 띄는 표시(굵은 글씨, 강조 색 등)로, "하"는 상대적으로 덜 강조되게 표시해줘.
   - 중요도가 높은 순서대로 정렬해서 보여줘도 좋아.

이번 단계에서는 캘린더 화면은 아직 만들지 마. 위 내용까지만 구현해줘.
```

### T2 결과 확인 체크리스트
- [ ] 화면에 "전체 완료율 OO%" 형태의 표시가 보인다.
- [ ] 할 일을 새로 추가하면 완료율(%)이 즉시 다시 계산되어 바뀐다.
- [ ] 할 일을 완료로 체크하거나 체크 해제하면 완료율이 바로 바뀐다.
- [ ] 할 일을 삭제하면 완료율이 바로 바뀐다.
- [ ] 목록에서 카테고리(BK/랩실/프로젝트/스터디/개인)마다 색이 다르게 구분되어 보인다.
- [ ] 목록에서 중요도(상/중/하)가 시각적으로 구분되어 보인다.
- [ ] 위 항목이 모두 정상이면 T3로 진행합니다.

---

## T3. 한 달 캘린더로 일정 보기

### 목표
`TASKS.md`의 "작업 3"에 해당하며, T1~T2에서 만든 할 일 데이터를 한 달 캘린더 화면 위에 표시하고
월 이동 기능을 추가하여 Smart Campus Planner MVP를 완성합니다.

### 그대로 복사해서 사용할 요청 프롬프트

```
지금까지 만든 Smart Campus Planner(할 일 등록/저장, 완료율 표시, 카테고리·중요도 구분 기능)에 이어서,
마지막 세 번째 단계 기능을 추가로 구현해줘. 기존 기능은 모두 그대로 유지하고, 아래 내용만 추가해줘.

[추가로 만들어야 할 것]
1. 목록 화면과 별도로(또는 같은 화면 안에서 전환 가능하게) 한 달 단위의 캘린더 화면을 만들어줘.
   - 요일(일~토)과 날짜 칸이 있는 일반적인 달력 모양으로 만들어줘.
2. 등록된 할 일 중 시작일부터 마감일까지의 기간에 해당하는 날짜 칸에는
   그 할 일의 제목이 표시되어야 해. (하루짜리 할 일은 그 날짜 한 칸에만 표시)
3. 캘린더에 표시되는 할 일도 카테고리별로 색깔이 구분되어 보이게 해줘.
   (목록 화면에서 사용한 것과 같은 카테고리 색상 규칙을 그대로 사용해줘.)
4. 캘린더 위쪽에 "이전 달", "다음 달" 버튼(또는 화살표)을 만들어서,
   버튼을 누르면 그 전달/다음 달의 달력과 해당 월의 할 일이 표시되도록 해줘.
5. 캘린더는 오늘 날짜가 포함된 달부터 처음 보여주고, 오늘 날짜 칸은 다른 날짜와 살짝 구분되게 표시해줘.

이 단계까지 완료되면 Smart Campus Planner의 첫 번째 버전(MVP)이 모두 완성되는 거야.
```

### T3 결과 확인 체크리스트
- [ ] 캘린더 화면에 요일과 날짜가 있는 한 달 달력이 보인다.
- [ ] 처음 열었을 때 오늘이 포함된 달이 보이고, 오늘 날짜가 구분되어 보인다.
- [ ] T1에서 등록한 할 일이 시작일~마감일에 해당하는 날짜 칸에 표시된다.
- [ ] 캘린더에서도 카테고리별로 색이 다르게 표시된다.
- [ ] "이전 달"/"다음 달" 버튼을 누르면 그 달의 달력과 할 일로 화면이 바뀐다.
- [ ] 목록 화면(T1~T2에서 만든 기능)도 여전히 정상적으로 동작한다.
- [ ] 위 항목이 모두 정상이면 PRD.md의 MVP 범위 구현이 모두 완료된 것입니다.

---

## 참고
- 본 문서는 요청 프롬프트를 정리한 문서이며, 실제 프로그램 코드는 아직 작성/수정하지 않았습니다.
- 각 프롬프트는 이전 단계 결과물을 "유지한 채로 추가 구현"하도록 작성되어 있으므로,
  반드시 T1 → 확인 → T2 → 확인 → T3 순서로 하나씩 진행해야 합니다.
- 진행 중 결과물이 기대와 다르면, 해당 단계 프롬프트 아래에 "이 부분이 이렇게 동작해야 하는데 다르게 동작한다"와 같이
  구체적인 문제 상황을 덧붙여서 같은 단계 내에서 먼저 수정 요청을 하고, 확인이 끝난 뒤 다음 단계로 넘어가세요.
